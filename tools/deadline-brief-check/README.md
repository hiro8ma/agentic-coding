# deadline-brief-check

依頼の文面の締切ごとに、固さ / 影響 / 途中の報告 / 理由の4つが書いてあるかを数える
Markdown や Slack の下書き、PR の本文の「## Review Deadline」の節に当てる
判定は語と形の決まった規則で行い、LLM は使わない
Python 3.9以降の標準ライブラリだけで動く

## なぜ作ったか

締切を日付だけで伝えると、受け手は「その日に終わっていなければ、延長を相談すればよい」と読むことがある
マネジメントの教材は、締切を伝えるときに次の4つを添えるよう勧めている

| 情報 | 中身 | 例 |
|---|---|---|
| 固さ | 動かせない期限か、目安か、仮か。急ぎかどうかも含める | 「動かせない」「目安」「急ぎではない」 |
| 影響 | 守れなかったら何が起きるか | 「間に合わないと展示に出せない」 |
| 途中の報告 | 間に合わなさそうなとき、いつまでに、何を、どう知らせるか | 「難しそうなら11/28までに Slack で知らせてほしい」 |
| 理由 | なぜその日なのか | 「12/5の展示の前に、12/1にテストを終えたい」 |

書いたつもりでも、読み返すと日付しか無いことが多い
この道具は、書いた文面に4つのどれが欠けているかを、毎回同じ規則で数える

## 締切の見つけ方

次の形か語がある行を、締切の記述として数える
英字は大文字と小文字を区別しない
全角の数字と `／` `：` は半角に直して見る

| 形 | 例 | 数えないもの |
|---|---|---|
| 年月日 | `2026/12/05` / `2026-12-05` / `2026年12月5日` | |
| 月日 | `12/5` / `12月5日` / `12月末` / `1月上旬` / `Dec 5` | 斜線の前後に数字か斜線が続く `data/1/2` |
| 時刻 | `17:00` / `17時` | `16:9` / `1時間` / `3時点` |
| 曜日 | `金曜` | |
| 相対の日 | `今日中` / `今週中` / `月内` / `週明け` / `月末` / `年度末` / `EOD` / `EOW` / `COB` | |
| 締切の語 | `期限` / `期日` / `締切` / `締め切り` / `〆切` / `納期` / `までに` / `deadline` / `due` | `due to` |

次の中は見ない

- フェンスのコードブロックと、インラインコード
- HTML のコメント（複数行も含む）とタグ
- `http://` / `https://` の URL

## 4つの情報の規則

締切の記述がある節（`--scope paragraph` なら段落）の文から、次の語を探す
1つでも当たれば、その情報が「ある」と判定する

### 固さ

| 規則 | 語 |
|---|---|
| 動かせない | 動かせない / ずらせない / 延ばせない / 延期できない / 厳守 / 必着 / 必達 / 遅くとも / 最終の期限（締切 / 〆切 / 期日）/ hard deadline / no later than / at the latest / strict / firm |
| 目安 / 仮 | 目安 / 暫定 / 仮の / 仮で / 仮置き / 仮決め / 仮押さえ / できれば / 可能なら / なるべく / 理想は / ずれても / 遅れても / 延びても / 前後して / 相談可 / 未定 / tentative / soft deadline / target date / if possible / ideally / flexible / TBD |
| 急ぎ | 急ぎ（「急ぎではない」も含む）/ 急いで / 至急 / 緊急 / 早め / 早いほど / なるはや / 優先度 / 最優先 / no rush / ASAP / urgent |

「仮説」「仮に」は仮に数えない
「助かる」は固さに数えない

### 影響

| 規則 | 語 |
|---|---|
| 止まる / ずれる | なくなる / 止まる / ブロック / 延期 / 後ろ倒し / ずれ込む / 持ち越す / 見送る / 待ちになる / これ待ち / 〜に回る / 遅れが出る / 〜てしまう / would slip / be delayed / block / otherwise |
| 影響 | 影響（「影響はない」も含む）/ 支障 / 困る / impact / affect |
| 間に合わないときの結果 | 同じ文に「間に合わないと」「守れなければ」「遅れると」「過ぎたら」「逃すと」「if we miss」などの条件があり、下の知らせる語が無い |

### 途中の報告

| 規則 | 語 |
|---|---|
| 間に合わないときの連絡 | 同じ文に、間に合わない見込みと、知らせる語の両方がある |
| 途中経過 | 途中経過 / 中間報告 / 進捗を共有（報告 / 連絡 / 教え）/ status update / check-in |

| 語の組 | 語 |
|---|---|
| 間に合わない見込み | 間に合わな / 遅れそう / 遅延 / 過ぎそう / 難しそう / 厳しそう / 無理そう / ずれそう / 延ばし / 延長 / 守れな / 終わらな / 詰まっ / can't make / miss / slip / delay / behind / extension |
| 知らせる語 | 連絡 / 知らせ / 教えて / 相談 / 共有 / 報告 / 一声 / 声をかけ / 言って / 伝えて / メンション / let me know / tell me / reach out / heads-up / ping / notify |

文は `。` `！` `？` `!` `?` と改行、英語の `.` の後ろの空白で区切る
同じ「間に合わない」でも、知らせる語がある文は途中の報告に、無い文は影響に数える

### 理由

| 規則 | 語 | 数えないもの |
|---|---|---|
| ため / ので | ため / ので / 動詞や形容詞に続き、句読点の前で終わる「から」/ なぜなら / というのも / 理由 / because / so that / in order to | あらためて / のでは / ここから、 |
| 前に / 後に | の前 / より前 / より先 / 〜前に / 〜前まで / 〜後に / 〜後で / てから / before / after / ahead of | 名前に / 以前に / 午前に / 事前に / 最後に / 前後に / 今後に / 午後に / 文の頭の「後で」 |
| 合わせる | に間に合わせる / に合わせる / に向けて / 逆算 | |

## 探す範囲

| `--scope` | 範囲 | 向いている文面 |
|---|---|---|
| `section`（既定） | 見出しから次の見出しの前まで。見出しが無い文面は全体を1つにする | PR の本文の節、短い依頼 |
| `paragraph` | 空行か見出しで区切った段落。見出しの行は読まない | 締切が複数ある長い依頼 |

節の範囲では、見出しの行も締切の記述として読む
「## Review Deadline」の節は、本文が「急ぎではない」だけでも、見出しの `Deadline` で締切のある節として数える

`--section NAME` を付けると、見出しの文が NAME の節だけを見る

- 大文字と小文字、空白の数、見出しの末尾のコロンと `#` の違いは無視する
- 節は次の同じか上の階層の見出しの前までとし、下の階層の見出しは節に含める
- 同じ名前の節が複数あれば全部を見る

## 出力

```text
$ python3 deadline_brief_check.py --section "Review Deadline" fixtures/pr_body.md
締切のある節 1件（4つがそろうのは1件）
固さ 1/1 / 影響 1/1 / 途中の報告 1/1 / 理由 1/1

1. 17〜26行目 見出し「Review Deadline」
   締切 17行目 ## Review Deadline
   締切 19行目 2026/11/20 17:00（目安、11/25の社内のデモより前に入れたい）
   締切 22行目 - 間に合わなさそうなら、11/19の昼までにこの PR のコメントで知らせてほしい
   固さ　　　 あり「目安」
   影響　　　 あり「遅れると」
   途中の報告 あり「間に合わな / 知らせ」
   理由　　　 あり「より前」
```

行の番号は、`--section` を付けても入力の全体の行で数える

`--json` を付けると、次の形で出す

| キー | 中身 |
|---|---|
| `summary` | `contexts`（締切のある節か段落の数）/ `complete`（4つがそろう数）/ 情報ごとの「ある」の数 |
| `contexts[].mentions` | 締切の記述の行の番号、行の文、当たった文字列 |
| `contexts[].info` | `firmness` / `impact` / `interim_report` / `reason` ごとの `present` と、当たった規則と文字列 |
| `contexts[].missing` | 欠けた情報のキー |

| 終了コード | 意味 |
|---|---|
| 0 | 締切が無いか、全部の締切に4つがそろう |
| 1 | 4つのどれかが欠けた締切がある |
| 2 | 入力を読めないか、`--section` の見出しが無い |

## 使う

```bash
python3 tools/deadline-brief-check/deadline_brief_check.py draft.md
python3 tools/deadline-brief-check/deadline_brief_check.py --scope paragraph draft.md
pbpaste | python3 tools/deadline-brief-check/deadline_brief_check.py
gh pr view 123 --json body --jq .body \
  | python3 tools/deadline-brief-check/deadline_brief_check.py --section "Review Deadline"
```

PR の本文は、全文ではなく `--section` で締切の節に絞って当てる
全文に当てると、ログや計測の日付まで締切に数える

## テスト

```bash
python3 -m unittest discover -s tools/deadline-brief-check
```

fixture とテストの文面は架空のもので、実在の組織や人の情報は含まない
17件のテスト（98件のサブテスト）が Python 3.9.6と3.15.0で通り、ruff check と ruff format で確かめた

次のように実装を壊すと、テストが落ちることも確かめた
壊した実装は、リポジトリの外の複製で試した

| 壊したところ | 落ちたテスト |
|---|---|
| フェンスを伏せない | フェンスの中の行 / チルダのフェンス |
| HTML のコメントを消さない | 複数行の HTML のコメント |
| URL を伏せない | URL の中の日付 / URL の後ろの和文 |
| 全角の数字を半角にしない | 全角の数字と斜線 |
| `due to` を除かない | 理由を表す due to |
| `1時間` を時刻に数える | 長さを表す1時間 |
| 知らせる語がある文も影響に数える | 間に合わないときの連絡は影響に数えない |
| 知らせる語が無くても途中の報告に数える | 知らせる語が無い / 見込みと知らせる語が別の文 / fixture の4つ |
| 文に分けずに全体で見る | 見込みと知らせる語が別の文 / fixture の4つ |
| 「あらためて」を理由に数える | あらためて |
| 名詞に続く「から」を理由に数える | 名詞に続くから |
| 文の頭の「後で」を理由に数える | 文の頭の後で |
| 「仮説」を仮に数える | 仮説は仮に数えない |
| 段落の範囲でも見出しを読む | 段落の範囲では見出しを読まない / 段落ごとに見る |
| 下の階層の見出しで節を切る | 下の階層の見出しは節に含める |
| 節の名前の大文字と空白を揃えない | 見出しの大文字と空白の違い |
| 重なる一致を捨てない | 年月日を漢字で書いた日付 / 月末と上旬 |
| 欠けがあっても終了コード0を返す | 欠けがあれば1 / 標準入力 / JSON の形 |
| 末尾の空行を範囲から外さない | 見出しの大文字と空白の違い |
| 見出しの末尾のコロンを外さない | 見出しの末尾のコロンと閉じる記号 |

## 限界

- 語があれば「ある」と判定し、語の意味は見ない
  - 「影響範囲」の影響や、別の件の「急ぎ」も数える
  - 否定や疑問の形も区別しない
- 4つの中身が十分かは見ない
  - 途中の報告に「いつまでに / 何を / どう」がそろうかは見ない
- 日付や時刻だけの行も締切に数える
  - ログ、計測、議事の日付を含む文書では、締切でない日付まで数える
- 目的の語を使わずに予定や出来事を並べた理由は見逃す
  - 「この日に merge して配信を始める」「仕様の確定は11/13」「次の定例のデモの準備」など
- 今起きている不具合だけを書いた影響は見逃す
  - 「CI が落ちている」は、待つと何が続くかを書いていないので数えない
- 節の範囲では、締切が複数あっても、4つの情報がどの締切のものかを区別しない
  - 段落の範囲にすると分けられるが、次の段落に書いた理由を見逃す
- 4字下げのコードブロック、下線で書く見出し、Slack の太字の見出しは扱わない
- `1/2` のような分数を日付に数える

## 確かめていないこと

- 規則は、実在の PR の Review Deadline の節を見てから書いた
  - 同じデータで測った一致は、初めて見る文面での一致より高く出やすい
- 途中の報告の規則が、実際の文面で正しく「ある」と判定するか
  - 試した実在の文面に、途中の報告を書いたものが無かった
- 英語の規則と Slack の下書きは、テストの例でしか確かめていない
