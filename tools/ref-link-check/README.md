# ref-link-check

エージェントの最後の答えに、URL のない Issue / PR の番号があれば、答えを止めて書き直させる Claude Code の Stop の hook
Python 3.9以降の標準ライブラリだけで動く

## なぜ hook にしたか

利用者の規則は「チャットの答えで Issue や PR に触れるときは、タイトルを書き、次の行に URL を書く。Markdown のリンク記法は使わない」というもの
エージェントは規則を書いた後も番号だけで触れ、4日で3回起きた
そのたびに規則へ「〜の場面でも」という但し書きが1つずつ増えた
但し書きを足すのは行動だけを直すやり方で、まだ書いていない場面では同じ失敗が起きる
そこで、答えが利用者に届く前に、モデルの外にある Stop の hook で答えの文を毎回同じ手順で調べる

## 止めるもの

| 書き方 | 例 |
|---|---|
| `#` と数字 | `#12` / `（#4821）` / `前回の#12と` |
| 接頭辞とハイフンと数字 | `IX-34` / `PROJ-8` / `E-501` / `MPC-77`（既定の接頭辞） |

見出し / 表のセル / 箇条書きの中も同じように調べる
次のどちらかに当たる番号は止めない

- 同じ行に `http://` か `https://` の URL がある
- 次の空でない行が URL で始まる
  - 行頭の空白、引用の `>`、URL を囲む `<` は許す

```text
#12 を直した                          ← 止める
ログインを直す（#12）
https://github.com/octo/app/pull/12   ← 前の行も含めて通す
```

## 止めないもの

| 例 | 止めない理由 |
|---|---|
| フェンスの中 / `` `#12` `` | コードの中。コードの中の URL も URL に数えない |
| `https://github.com/octo/app/pull/12#issuecomment-1` | URL の中 |
| `#team-news` / `#2026-offsite` | チャンネル名。`#` の後ろが英字か、数字の後ろにハイフンが続く |
| `#fff` / `#1a2b3c` / `#000000` | 16進の色。英字を含むか、0で始まる |
| `707f592` / `1E-10` | コミットのハッシュと指数表記。`#` がないか、接頭辞の前に英数字がある |
| `# 概要` / `## 2. 手順` | 見出しの記号 |
| `&#12;` / `page#12` / `items/#12` | `&` / 英数字 / `/` の後ろの `#` |
| `TYPE-12` / `RULE-2026` / `docs/E-501/` / `IX-12-fix` / `ix-12` | 語やパスの一部。接頭辞は大文字と小文字を区別する |

英数字の境界は ASCII だけで判定する
Python の `\w` は和文の文字も含むので、`\w` で判定すると「前回の#12と」を見逃すため

## 答えの文の取り方

1. 標準入力の `stop_hook_active` が true なら、何も読まずに通す
   - Stop の hook が止めた後の答え直しは調べない。止め続けて抜けられなくなるのを防ぐため
2. `last_assistant_message` が文字列なら、それを答えの文とする
   - 公式の文書は、Stop の時点の transcript が最後の答えを含むとは限らないとして、この欄を使うよう勧めている
3. 無ければ `transcript_path` の JSONL を末尾から読む
   - 最後の利用者の入力か tool_result、または tool_use より後にある、`type` が `assistant` の行の text をつなぐ
   - 同じターンでも、tool_use より前の文は読まない
   - `isSidechain` が true の行（サブエージェント）は飛ばす
   - 64KiBずつ読み、末尾から16MiBで打ち切る。手元の371MBの transcript で、起動を含めて24msで終わった

## 理由の文

止めると、Claude に次の文が渡り、Claude が答えを書き直す

```text
答えに、URL のない Issue / PR の番号がある
- 4行目「- #13 と E-501 は CI 待ち」の #13 / E-501
番号で触れる項目ごとに、タイトルを書き、次の行に URL をそのまま書く（Markdown のリンク記法は使わない）
タイトルと URL を確かめてから、答えを書き直す
URL を確かめられない項目は、確かめられないと書く
```

## Claude Code に入れる

`~/.claude/settings.json` の `hooks.Stop` に足す
Stop は matcher を使わないので、`matcher` は書かない
すでに `Stop` があれば、その配列に足す

```bash
mkdir -p ~/.claude/hooks
cp tools/ref-link-check/ref_link_check.py ~/.claude/hooks/
```

```json
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "python3 \"$HOME/.claude/hooks/ref_link_check.py\"",
            "timeout": 10
          }
        ]
      }
    ]
  }
}
```

`timeout` を過ぎると、Claude Code は hook の出力を捨てるので、答えは止まらない

## 設定

| 引数 / 環境変数 | 中身 |
|---|---|
| `--prefixes IX,PROJ` | 接頭辞をカンマ区切りで渡す。環境変数より優先する |
| `REF_LINK_CHECK_PREFIXES` | 同じ形の環境変数。引数も環境変数もなければ `IX,PROJ,E,MPC` |

- 空にすると `#` だけを見る
- 英字で始まらない名前と、英数字以外を含む名前は捨てる

## 通すとき

次のときは、何も出さずに終了コード0で通す
hook の不具合で、全部の答えを止めないため

- `stop_hook_active` が true
- 標準入力の JSON が読めないか、オブジェクトでない
- transcript が無いか読めない。書きかけの行や UTF-8 でない行がある
- 引数が誤っている
  - Stop の hook が終了コード2を返すと、答えを止めてしまうため
- 判定の処理で例外が起きた

## 試す

```bash
echo '{"hook_event_name":"Stop","stop_hook_active":false,"last_assistant_message":"#12 を直した"}' \
  | python3 tools/ref-link-check/ref_link_check.py
```

## テスト

```bash
python3 -m unittest discover -s tools/ref-link-check
```

transcript は合成のもので、実在の組織や人の情報は含まない
Python 3.9.6と3.15.0で通ることを確かめた

次のように実装を壊すと、テストが落ちることも確かめた
壊すときは、変異ごとに作業用のディレクトリへ写して壊し、このディレクトリの実装は変えていない

| 壊したところ | 落ちたテスト |
|---|---|
| `stop_hook_active` を見ない | `stop_hook_active` なら止めない（答えの文から読むときと transcript から読むとき） |
| 次の行の URL を見ない | 次の行に URL を置いた通す例6件 / URL の行の次の行の番号 / URL のある答えの hook |
| フェンスとインラインコードを伏せない | コードの通す例7件 / フェンスの後ろの番号 / インラインコードの URL |
| フェンスだけ伏せない | フェンスの通す例5件 / フェンスの後ろの番号 |
| インラインコードだけ伏せない | インラインコードの通す例2件 / インラインコードの URL |
| 接頭辞の前の境界を外す | 語の中の接頭辞 / パスとファイル名の中の番号 / 指数表記 |
| 接頭辞の後ろの境界を外す | 長い識別子の一部 |

## 限界

- 番号と URL の対応は見ない
  - 同じ行の URL が別のものを指していても通す
  - 次の行の URL が1本でも、前の行の番号を全部通す
- タイトルがあるかは見ない。`#12` の次の行に URL があれば通す
- `#333333` のように、0以外で始まり数字だけで書いた色は番号と区別できない。色はコードの中に書く
- 英字の直後の `#`（`PR#12`）と、全角の `＃12` は見ない
- 4字下げのコードブロックはコードとして扱わない。箇条書きの下げと区別しないため
- インラインコードは1行の中で閉じるものだけを扱う
- `stop_hook_active` が true のときは調べない
  - 答え直した文に番号が残っていても通す
  - ほかの Stop の hook が止めた後の答えも調べない
- 最後の答えだけを調べる。途中の文と、サブエージェントの報告は調べない

## 確かめていないこと

- 実際の Claude Code のセッションで、`last_assistant_message` が届くことと、block で答え直させること
  - 入出力の形は公式の文書に合わせ、テストでは標準入出力だけを確かめた
- 最後の答えに text の block が複数あるときに、`last_assistant_message` に全部が入るか
- transcript の行の形。公式の文書に書かれておらず、手元の Claude Code 2.1.318の transcript に合わせた
- Codex の Stop の hook での動き
