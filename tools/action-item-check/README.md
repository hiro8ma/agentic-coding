# action-item-check

会議の議事録のアクションの項目ごとに、担当 / 期限 / 理由の3つが書いてあるかを数える
Markdown のファイルかディレクトリを読み、ファイルごとと全体の件数と、欠けた項目を出す
「担当 / 内容 / 期限」の3つの欄で書いたチェックボックスの行は、欄で読む
担当が組織か複数の当事者の項目は、担当ありのまま別に数える
判定は語と形の決まった規則で行い、LLM は使わない
Python 3.9以降の標準ライブラリだけで動く

## なぜ作ったか

会議の後のアクションを「資料を作る」とだけ書くと、次の会議で、誰がいつまでにやるはずだったかから話し直すことになる
マネジメントの教材は、アクションを「何を、いつまでに、誰が」で合意し、新しいアクションは理由とともに決めるよう勧めている

| 情報 | 中身 | 例 |
|---|---|---|
| 担当 | 誰がやるか | 「犬山さん」「@inuyama」「（猫田）」 |
| 期限 | いつまでにやるか | 「11/20」「来週」「次回まで」 |
| 理由 | なぜやるか | 「入稿が11/21なので」「目的は告知」 |

「何を」は項目の文そのものなので、この道具は見ない
書いたつもりでも、読み返すと「何を」しか無い項目が多い
この道具は、3つのどれが欠けているかを、毎回同じ規則で数える

## deadline-brief-check との分担

期限の形と理由の語は、同じリポジトリの `tools/deadline-brief-check` の規則を読み込んで使う
`deadline_brief_check.py` を import するので、2つの道具を `tools/` の下に並べて置く
規則を二重に持たないためで、足りない語だけをこの道具で足す

deadline-brief-check に足さず別の道具にしたのは、数える単位と CLI の形が違うため

- deadline-brief-check は、締切のある節か段落を数え、固さ / 影響 / 途中の報告 / 理由の4つを見る
  - 読むのは1つのファイルか標準入力
- この道具は、アクションの項目を数え、担当 / 期限 / 理由の3つを見る
  - 複数のファイルとディレクトリを読み、`--report-only` を持つ

| 部分 | deadline-brief-check から使うもの | この道具で足すもの |
|---|---|---|
| 伏せる部分 | `mask`（フェンス / インラインコード / HTML のコメントとタグ / URL / 全角の数字） | タグを消す前に、Notion のメンションを読む |
| 見出し | `parse_heading` | Notion の見出しの属性（`{toggle="true"}` など）を外す |
| 期限 | `deadline_matches`（締切の見つけ方の全部） | 相対の期限の語 |
| 理由 | 理由の規則のうち「ため / ので」と「合わせる」 | 目的 / 背景 / なぜ などの語 |

deadline-brief-check の規則を変えると、この道具の判定も変わる
変えたときは、両方のテストを流す

## 項目の見つけ方

### アクションの節

見出しか太字の行の文に次の語があれば、アクションの節として読む
英字は大文字と小文字を区別しない

| 語 | 数えないもの |
|---|---|
| Next Action / Next Actions / NA / TODO / ToDo / To-Do / Action Items / Action Item | `NAME` / `N/A` / `DNA` のように、英数字と続く NA |
| アクション / 次のアクション / 宿題 / やること | リアクション |

- 語が文の一部にあれば節にする
  - 「次回までの宿題」「NA（11/13）」も節にする
- 太字の行は、行の全体が `**…**` か `__…__` のもの
  - 末尾のコロンは外す
- Notion の見出しの末尾の属性は外して読む

| 節の始まり | 節の終わり |
|---|---|
| 見出し | 同じか上の階層の見出しの前（下の階層の見出しは節に含める） |
| 太字の行 | 次の見出しか、同じか浅い字下げの太字の行の前 |
| 太字の箇条書き（`- **NA**`） | その箇条書きと同じか浅い字下げの行の前（子の箇条書きだけを節にする） |

### 項目

- アクションの節の中の箇条書きを、1つずつ項目にする
  - 節の中で最初に出た箇条書きの字下げを項目の階層にし、それより深い箇条書きは親の項目の一部として読む
- どの節にあっても、チェックボックスの行（`- [ ]` / `- [x]`）は項目にする
  - 節の中のチェックボックスは、節の項目として1回だけ数える
  - 入れ子のチェックボックスは、親の項目の一部として読む
- 箇条書きの印は `-` / `*` / `+` / `1.` / `1)` / `・` / `•`
- 字下げのタブは4字として読む
  - Notion の書き出しのタブの入れ子も読む

| 項目の後ろの行 | 扱い |
|---|---|
| 項目より深い字下げの行 | 続き（空行を挟んでも続き） |
| 空行を挟まない、字下げの無い文の行 | 続き（Markdown の続きの行） |
| 項目と同じか浅い字下げの箇条書き | 閉じて、次の項目にする |
| 空行の後の、字下げの無い段落 | 閉じる |
| 見出しと、項目と同じか浅い字下げの太字の行 | 閉じる（見出しの節の中の太字の行なら、節は続く） |

次の中は見ない（deadline-brief-check の `mask` と同じ）

- フェンスのコードブロックと、インラインコード
- HTML のコメント（複数行も含む）とタグ
- `http://` / `https://` の URL

### Notion のメンション

Notion の書き出しのメンションのタグは、タグを消す前に次のように読む

| タグ | 読み方 |
|---|---|
| `<mention-user url="user://..."/>` | 担当 |
| `<mention-date start="2026-11-20"/>` | `start` の年月日を期限の日付として読む（時刻つきの `start` も年月日だけを読む） |
| `<mention-page …>` とそのほかのメンション | 中の文だけを読み、括弧の名前には数えない |

- 閉じタグのある形（`<mention-user url="…">名前</mention-user>`）も読む
- 出力の項目の文では、メンションを中の文か年月日にして出す
  - 中の文が無いユーザーは `@user` と出す

## 欄の形と文の形

項目は、1行目の形で2つの読み方に分ける

| 形 | JSON の `form` | 当てはまる項目 | 読み方 |
|---|---|---|---|
| 欄の形 | `columns` | チェックボックスの行で、1行目が ` / ` でちょうど3つの欄に分かれる | 「担当 / 内容 / 期限」の欄として読む |
| 文の形 | `text` | それ以外 | 下の語の規則で、項目の行と入れ子の行の全部から探す |

### 欄の形

`- [ ] 犬山 / 共有されたファイルの中身を確かめる / 11/20` のような行を読む

| 情報 | 読むところ | 「ある」にする条件 | `evidence` の `rule` |
|---|---|---|---|
| 担当 | 1つ目の欄だけ | 欄が空 / 未定 / TBD / `-` のどれでもない | 欄の形の担当 |
| 期限 | 3つ目の欄だけ | 欄が空 / 未定 / TBD / `-` のどれでもない | 欄の形の期限 |
| 理由 | 2つ目の欄と入れ子の行 | 下の理由の規則に当たる | 理由の規則の名前 |

- TBD は大文字と小文字を区別しない
- 欄の文の中身は見ない
  - 「Taro Inuyama」も「犬山」も「金曜日配信前まで」も、そのまま「ある」にする
- 2つ目の欄の「次回」「金曜」などは、期限に数えない
  - 3つ目の欄が未定なら、期限なしにする
- 入れ子の行の担当と期限は読まない
- 欄の区切りは、前後に空白か行の端がある `/`
  - 全角の `／` も読む（deadline-brief-check の `mask` が半角に直す）
  - `犬山/資料/未定` のように、空白の無い斜線では分けない
  - 1つ目の欄が空の `- [ ] / 資料を作る / 11/20` も、3つの欄に数える
- 欄が2つ以下か4つ以上の行と、チェックボックスでない行は、文の形として読む

## 語の規則

文の形の項目では、担当 / 期限 / 理由をこの規則で探す
欄の形の項目では、理由だけをこの規則で探す
1つでも当たれば「ある」と判定する

### 担当

| 規則 | 当たるもの | 数えないもの |
|---|---|---|
| Notion のユーザー | `<mention-user>` | |
| @名前 | `@inuyama` / `＠犬山` | メールアドレスの `@` / `@channel` / `@here` / `@everyone` |
| 担当の語 | 担当 / owner / assignee / assigned to | |
| 〇〇さん | 漢字 / カタカナ / 英字に続く「さん」 | ひらがなに続く「さん」（たくさん）/ 皆さん / お客さん |
| 括弧の名前 | 行頭か行末の `()` / `（）` / `【】` / `[]` / `［］` の中の、人名らしい語 | 下に書く |

括弧の名前は、括弧の中を空白 / `/` / `・` / `、` / `,` / `&` で区切り、次の語が1つでもあれば担当にする

- 漢字1〜3字 / カタカナ2〜10字 / 英字2〜20字（`.` と `-` を含んでよい）の語
  - 末尾に「さん / くん / 様 / 氏」が付いてもよい
- 下の「担当の種類」の組織の語を含む語（「（お客さま）」のように、名前の形に当たらなくてもよい）
- 「（猫田、11/20）」は、猫田が名前の形に当たるので担当にする
- 手がかりの文は、当たった語を「・」でつないだもの（「（猫田/鳥井）」は「猫田・鳥井」）

次の語は名前に数えない

- 数字を含む語と、4字以上の漢字（「11/20」「資料作成」）
- 期限か理由の規則に当たる語（「来週」「金曜」「目的」）
- 3字以上の大文字の英字（「API」「WIP」）
- 状態と曜日の語（済 / 未定 / 完了 / 対応中 / 確認中 / 保留 / 任意 / 仮 / 案 / 再掲 / 優先 / 重要 / 参考 / 補足 / 月 / 火 / 水 / 木 / 金 / 土 / 日 など）
  - 全部はコードの `NOT_NAMES` にある
- 行頭の `[…]` がリンクの文（`[資料](https://…)`）のとき
- 開きと閉じが合わない括弧（`（犬山]`）

### 期限

| 規則 | 当たるもの |
|---|---|
| 日付 / 締切の語 | deadline-brief-check の締切の見つけ方の全部（`11/20` / `11月20日` / `2026-11-20` / `17:00` / `金曜` / `今週中` / `月末` / `EOD` / `期限` / `までに` / `due` など） |
| 相対の期限 | 明日 / 明後日 / 今週 / 来週 / 再来週 / 翌週 / 来月 / 翌月 / 週末 / 月初 / 週内 / 月内 / 年内 / 年度内 / 次回 / 次の定例（会議 / ミーティング / 打ち合わせ / MTG）/ 今日まで / 本日まで / 今月まで / `（金）` のような括弧の曜日 / today / tomorrow / tonight / this week / next week / next time / next meeting / end of day（week / month）/ 英語の曜日 |

相対の期限の語は、この道具だけで足す

- アクションの行では、「来週」「明日」「次回」は期限として書かれることが多い
- 依頼の文面では、「来週の検証の準備」のように期限でない使い方が多い
  - deadline-brief-check に足すと、締切でない段落まで数える

### 理由

| 規則 | 当たるもの | 出どころ |
|---|---|---|
| ため / ので | ため / ので / 動詞や形容詞に続き、句読点の前で終わる「から」/ なぜなら / というのも / 理由 / because / so that / in order to | deadline-brief-check |
| 合わせる | に間に合わせる / に合わせる / に向けて / 逆算 | deadline-brief-check |
| 目的 / 背景 | 目的 / 背景 / 狙い / 意図 / なぜ / why / purpose / goal | この道具 |

deadline-brief-check の理由の規則のうち、「前に / 後に」は使わない

- 締切の文面では、「11/25のデモより前に入れたい」が、その日である理由になる
- アクションの「定例の前に送る」「確認してから送る」は順番や時機で、なぜやるかを書いていない

## 担当の種類

担当が「ある」項目を、人（`person`）と、組織か複数の当事者（`group`）に分ける
どちらも担当ありのまま数え、group の件数を別に出す

担当の手がかりの文に次のどれかがあれば group にし、無ければ person にする

| 種類 | 当たるもの |
|---|---|
| 組織の語 | 側 / 先方 / お客さま / お客様 / 弊社 / 当社 / 御社 / 貴社 / 全員 / 両者 / 双方 / 各位 / チーム / 一同 |
| つなぎの記号 | `・` / `、`（「弊社 側・先方」「犬山・猫田」） |

| 手がかり | 見る文 |
|---|---|
| 欄の形の担当 | 1つ目の欄の全体 |
| 括弧の名前 | 当たった語を「・」でつないだ文 |
| @名前 / 〇〇さん | 当たった文字列 |
| Notion のユーザー / 担当の語 | 組織の語を含まないので、これだけなら person |

  - 入れ子のある項目は「10〜11行目」のように範囲で出す

| キー | 中身 |
|---|---|
| `summary` | `files`（読んだファイルの数）/ `items`（項目の数）/ `complete`（3つがそろう数）/ `missing`（`owner` / `due` / `reason` ごとの欠ける数）/ `owner_kind`（担当がある項目の `person` と `group` の数） |
| `files[].path` / `files[].summary` | ファイルの名前と、ファイルごとの件数（`summary` から `files` を除いた形） |
| `files[].items[]` | 項目ごとの `start_line` / `end_line` / `text` / `source`（`section` か `checkbox`）/ `section`（節の見出しか太字の行の文、節の外なら null）/ `form`（`columns` か `text`）/ `owner_kind`（`person` か `group`、担当が無ければ null）/ `info`（3つごとの `present` と、当たった規則と文字列）/ `missing`（欠けた情報のキー） |

| 終了コード | 意味 |
|---|---|
| 0 | 項目が無いか、全部の項目に3つがそろう / `--report-only` を付けた |
| 1 | 3つのどれかが欠けた項目がある |
| 2 | パスが無い / ファイルを UTF-8 で読めない / パスを渡していない（`--report-only` を付けても2） |

入力の誤りがあると、ほかのファイルも出力せずに2を返す

## 使う

```bash
python3 tools/action-item-check/action_item_check.py minutes.md
python3 tools/action-item-check/action_item_check.py minutes/ notes.md
python3 tools/action-item-check/action_item_check.py --json minutes/ > actions.json
python3 tools/action-item-check/action_item_check.py --report-only minutes/
pbpaste | python3 tools/action-item-check/action_item_check.py -
```

| 引数 | 動き |
|---|---|
| `PATH` | 読む Markdown のファイルかディレクトリ（いくつでも渡せる、`-` で標準入力を読む） |
| `--json` | JSON で出す |
| `--report-only` | 欠けがあっても終了コード0を返す（入力の誤りは2のまま） |

- ディレクトリは、下の階層の `*.md` を名前の順に読む
  - `.` で始まるディレクトリは読まない
- ファイルを直に渡したときは、拡張子を問わず読む
- 同じファイルを2回渡しても、1回だけ読む
- UTF-8 で読み、先頭の BOM は外す
- 議事録の全体に当てると、議題の中のチェックボックスも項目に数える
  - アクションの節だけを見たいときは、節を抜き出してから当てる
- 欄の形と文の形がどれだけあるかは、JSON の `form` で数える
  - 欄の形で担当や期限が欠けた項目は、欄に未定 / TBD / `-` と書いたか、欄を空にした項目

## 限界

- 語があれば「ある」と判定し、語の意味は見ない
  - 「担当者を決める」のように、担当の語がアクションの中身である行も、担当ありに数える
  - 「先方の犬山さんに連絡する」のように、相手の名前も担当に数える
  - 「期限は未定」「担当は未定」も、期限の語と担当の語で「ある」に数える
  - 時刻だけの行（「17:00の会議の資料を送る」）や、「来週のリリースの準備」のように期限でない相対の語も、期限に数える
- 理由の語がアクションの中身である行も、理由ありに数える
  - 「目的を決める」「背景を調べる」「理由を確認する」
- deadline-brief-check の「ので」の規則は、理由でない「ので」にも当たる
  - 「確認したいのですが」「既存のもので進める」も理由ありに数える
- 括弧を使わない名前の書き方は、欄の形でなければ担当に数えない
  - 「犬山: 資料を作る」「犬山）資料を作る」「資料を作る → 犬山」
  - チェックボックスでない「- 犬山 / 資料を作る / 未定」も、文の形として読むので担当に数えない
- 欄の形は、欄の文の中身を見ない
  - 「要調整」「TBA」「?」「確認中」も、担当か期限の「ある」に数える
  - 並列を ` / ` で書いたチェックボックスの行も、欄の形として読む
    - `- [ ] 表示条件 / フィルタ / スタイルを直す` は、担当と期限が「ある」になる
  - 2つ目の欄に ` / ` があると欄が4つ以上になり、文の形として読む
  - 3つ目の欄が未定でも、入れ子の行に書いた期限は読まない
- 担当の種類は、語と記号で見る
  - 「タロウ・イヌヤマ」のような、中黒の入った1人の名前も group にする
  - 組織の語を含まない組織の名前（会社の名前だけ）は person にする
  - 「担当 先方」のように担当の語の後ろに書いた組織は、担当の語でしか当たらないので person にする
- 4字以上の漢字の名前（「犬山一郎」）は、括弧の中で空白で区切らないと担当に数えない
- 括弧の中の漢字3字以内とカタカナと英字の語は、名前と区別しない
  - 「（デザイン）」「（PR）」「（全員）」「（後日）」「（依頼）」「【課題】」も担当に数える
  - 3つの規則の中で最も誤りやすく、担当の欠けは少なめに出る
  - JSON の `evidence` の `rule` が「括弧の名前」だけの項目を分けると、数え直せる
- 理由の語を使わない理由は見逃す
  - 「漏れを無くせるように」のような「ように」の目的
  - 「先方から依頼があった」のように、背景を事実だけで書いたもの
- 親の箇条書きを見出しの代わりに使い、子にアクションを並べた書き方は、親と子をまとめて1件に数える
  - 「- 犬山さん」の下に「- 資料を作る」「- 連絡する」を並べると、1件で担当ありになる
- 小見出しや太字の行で担当ごとに分けた書き方（「### 犬山さん」の下の箇条書き）は、小見出しの名前を担当に数えない
- 見出しの節の中の太字の行（「**メモ**」）は、節を閉じない
  - その後ろの箇条書きもアクションに数える
- 次の書き方は、アクションの節として読まない
  - 表の行（`| 犬山 | 資料を作る | 11/20 |`）
  - 太字でない文の行のラベル（「Next Action:」「【宿題】」「■ NA」）
  - Notion のトグル（`<details><summary>NA</summary>`）
    - 中のチェックボックスだけは項目に数える
- 4字下げのコードブロックと、下線で書く見出しは扱わない
- `1/2` のような分数を日付に数える（deadline-brief-check と同じ）
- 斜線の直後の日付は期限に数えない（deadline-brief-check がパスの中の数字を除くため）
  - 「資料を作る（犬山/11/20）」は期限なしになる

## 確かめていないこと

- 実在の議事録での、取りこぼしと誤検知の件数
  - 規則は、教材の勧めと架空の文面から書いた
  - 実在の議事録に当てると、行の多くが欄の形で、名前に「さん」も括弧も無く、担当を拾えなかった
  - そのため欄の形を足した
  - 欄の形を足した後の取りこぼしと誤検知の数は、まだ数えていない
- Notion の書き出しの形は、メンションのタグ / タブの入れ子 / 見出しの属性に合わせて書いた
  - 実物の書き出しにある形の全部は確かめていない
- 英語の議事録は、テストの例でしか確かめていない
