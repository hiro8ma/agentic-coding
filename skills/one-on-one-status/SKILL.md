# 1on1 の状況確認

1on1 の相手が、シートを一見して「本人がその週に何をやったか」を理解できる文章を作る
読み手は 1on1 の相手で、書く対象は本人（このスキルを使う人）の活動
相手は作業の経緯を知らない前提で書く

## 手順

### 1. シートの形を確かめる

- シートの URL か、貼り付け先の既存の書き方をもらう。あれば読んで、その形に合わせる
- 無ければ `assets/template.md` の形（名前 → プロジェクト → 箇条書き）を使う
- 名前の欄の表記（呼び名など）は、シートにあるものをそのまま使う

### 2. 期間を決める

- 既定は、今週の月曜から今日まで。前回の 1on1 の日が分かれば、その翌日からにする
- 期間は絶対日付で持つ（「今週」のまま検索しない）

### 3. 活動を拾う

使えるツールだけを使い、拾えなかった情報源は最後に報告する

| 情報源 | 拾うもの | 例 |
| --- | --- | --- |
| GitHub | 期間内にマージした PR / 開いている PR とそのレビュー状況 | `gh pr list --author @me --state merged --json number,title,mergedAt` |
| タスク管理（Notion など） | 自分が担当のプロジェクトと Issue、その状態 | Projects / Issues のデータベースを検索する |
| Slack | 自分が書いた投稿と、返事をもらったスレッド | 依頼への対応、相手からの確認結果、決まったこと |
| この会話 | 今日までにこの会話で進めた作業 | まだ PR や Issue に表れていないもの |

- PR の本数は一覧から数える。記憶で書かない
- Slack と Notion は、事実の裏付け（誰が何を確認したか、何が決まったか）に使う。雑談は拾わない

### 4. プロジェクトごとにまとめる

- 見出しは、タスク管理にあるプロジェクトの正式な名前にし、そのページへのリンクを付ける。名前を作らない
- 対応するプロジェクトが無い活動は「その他」に置く
- 並び順は、優先度の高いプロジェクトから

各プロジェクトには、次の順で書く

1. やったこと: 成果を1行で書き、その下に対応する Issue のリンクを入れ子で並べる。PR を1本ずつ並べず、相手にとって意味のあるまとまりにする
2. 残り: 「残り」という項目を1つ置き、その下に終わっていない Issue のリンクを並べる。各行の末尾に、止まっている理由を括弧で添える（レビュー待ち / 相手の確認待ち / 未着手）
3. 相談: 相手に決めてほしいこと。関係する「残り」の Issue の下に入れ子で置き、選択肢を並べる

Issue のリンク

- やったことにも残りにも、タスク管理にある Issue のリンクを付ける。リンクの文字は Issue の題名にする
- Issue は、プロジェクトに紐づく一覧から状態（完了 / レビュー中 / 未着手）ごとに引く。記憶で題名や URL を書かない
- 1つの成果に付ける Issue は2〜4件にする。細かい修正の Issue まで全部は並べない
- 対応する Issue が無い項目は「Issue なし」と添える。Issue にすべき作業なら、最後の報告で挙げる

開発以外の活動

- 採用 / 組織づくり / 社内への提案など、PR に表れない活動もプロジェクトとして並べる。周りから見えにくい活動ほど、目的と今の段階を1行ずつ書く
- 候補者の氏名や評価など、個人が分かる情報は書かない。「選考の進め方に意見を出した」のように、自分がした行為だけを書く

### 5. 書き方

- 一文を短くし、1項目を1〜2行に収める
- PR 番号や Issue の ID だけで説明しない。何をしたものかを言葉で書く
- 「ほぼ」「だいたい」を使わず、数と状態で書く（本数 / 件数 / 日付 / レビュー待ちか）
- 確かめた範囲を正確に書く。PC でしか見ていなければ「PC で確認」と書き、確かめていないことを済んだように書かない
- 相手が知らない社内の略語と識別子は、言い換えるか一言で補う
- 分量は、プロジェクトごとに3〜6項目を目安にする。それを超えるなら、細かい修正をまとめる
- 仕事の場所に出す文章なので、私的な情報や、相手に見せる必要のない認証情報 / 内部の ID は書かない

### 6. 出力

- まとめをファイルに保存し、クリップボードに入れ、同じ文面を会話にも出す
- シートへの書き込みは、頼まれたときだけ行う。書き込む前に、シートの今の内容を読み直す
- 最後に次を報告する
  - 拾えなかった情報源
  - 仮に付けた名前や、推測で置いた「相談」
  - 確かめていない事実

## 最終確認

- プロジェクト名は正式な名前で、リンクが付いているか
- 経緯を知らない相手が、各項目だけで「何が終わり、何が残り、何を決めてほしいか」を読み取れるか
- 数字は、一覧から数えた値か
- 削っても相手の理解が変わらない項目が残っていないか
