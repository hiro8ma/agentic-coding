# 分析レポート

読み手が冒頭だけで「何が分かり、何を決めればよいか」を掴めるように書く
文章の書き方は `japanese-tech-writing` に従う

## 章立て

ドキュメンテーションガイドラインのレポートのテンプレートに合わせ、次の順に置く
見出しに番号は付けない

| 章 | 書くこと |
| --- | --- |
| 目的 | 何を把握し、何を決める材料にするか |
| 概要 | 主要な結論 / 決めてほしいこと / 実施前に要る作業 / 用語 |
| イントロダクション | 分析を始めた経緯、確かめる問い、前提となる外部の情報 |
| データ収集方法 | 対象と期間、集計の条件、調べ方、SQL とその置き場所、ログの定義、データの制約 |
| 結果 | 問いごとの判定の表、仕組み、数値の表、画像 |
| 考察と今後の展望 | 判断、推奨アクションと成功指標、未検証事項 |
| 参照 | 関連ページ、共有した後に結論を直した経緯 |

- 同じ事実は1か所にだけ書く。概要は結論と判断に絞り、結果の言い直しにしない
- 前提となる外部の情報（競合の会社情報など）は、本文には判断に要る点だけを3行程度で残し、詳細はトグルか付録に入れる

## 概要

- 主要な結論は3つまでにする。それぞれ比べる相手か数値を含める
- 決めてほしいことは、選択肢の形で並べる
- 実施前に要る作業は、未確定の数値を確定させる作業を含める。対応する Issue をリンクで添える
- 用語は、読み手が初めて見る指標や区切り（「先頭3件」など）だけを定義する

## 問いと判定

- 仮説は、関係者から出た問いの言葉で書く。誰の話かを添える
- 判定は平易な言葉にする。「採択 / 棄却」ではなく「正しい / 一部正しい / 誤り / 分からない」を使う
- 程度を問う仮説（「非常に高い」など）は、「中くらい」のようなあいまいな語で受けず、正誤を決めて順位を添える（例 誤り（7枠中4番目））
- 「最も高い」「非常に高い」と書くときは、比べた集合を明示する。全体の中の順位も示す
- 関連が見えただけのときは、判定を「分からない（関連はある）」に留める
  - 表示の多さ / 位置 / 好みのように、原因の候補を分けられない理由を書く
  - 位置や表示のログが無いとき、クリックや購入をその仕組みの寄与と読まない

## 数値

- 分子と分母の単位を揃える。揃わないときは、分子と分母をそれぞれ書き、目安として扱う
- 表ごとに数える単位（クリック / セッション / PV / 利用者）を書く。単位が違う表の数値が合わない理由も書く
- 途中集計の数値には、件数と条件（識別子の有無、期間など）を添える。最終集計で置き換える
- 1回ごとの範囲と延べの割合を区別する。最小値だけを取り出して「〜まで下がった」と書かない
- 紐づけ方に既知の問題がある数値は、直すまで目安と書き、直す作業を推奨アクションに入れる

## 実験の設計

- 最小検出差と、非劣性を示すのに要る期間は別に出す。最小検出差は差を見つけるための目安と書く
- 非劣性は、同じ期間に無作為に分けた群どうしの比（または差）の信頼区間で判定する。片方の群だけの信頼区間や過去の値との比較で判定しない
- 始める前に決めることを並べる
  - 割り付けの単位と、再訪したときに同じ群に固定するか
  - 主に分析する単位
  - 非劣性のマージンとその根拠、片側の有意水準
  - 再訪による偏りを入れた必要な期間
  - 主な指標
- セッションを互いに独立とみなした計算は参考値と書く
- 少ない割合で始めて問題が出ないことの確認と、全面展開してよいかの判定は分ける

## 推奨アクションと成功指標

- アクションは実施する順に表にし、成功指標と判定条件を添える
- 閾値（95%など）には根拠を書く。強い根拠が無ければ目安と書く
- 計測の網羅率を指標にするときは、欠けが端末や群で偏っていないことも条件に入れる

## 誤りを直した経緯

共有した後に結論を直したときだけ、参照の章に次の5点を残す
共有する前の書き直しは、前の版を読んだ人がいないので残さない。経緯はコミットのメッセージで追える
- 経緯（何を前提に、どう判断したか）
- 確認方法
- 結果（数値を具体的に）
- 判断（どう直したか）
- 誤りの原因

## 書き終えたら

- 概要だけを読んで、結論 / 決めること / 先にやる作業が分かるか
- 「最も」「高い」「効いている」に、比べる相手と根拠があるか
- 関連を寄与として書いていないか
- 単位の違う数値を並べていないか
- 外部からのレビューを取り込んだときは、指摘ごとに SQL やデータで裏付けを取ってから直す
