# 機構ごとのバイパス条件

「有効にしたのに効かない」が起きる代表的な経路。
対象の機構がここにあれば、有効化の手順より先にこちらを読む。

## PostgreSQL Row Level Security

| 誰が | 何が起きるか |
|---|---|
| superuser | 無条件でバイパスする。`FORCE ROW LEVEL SECURITY` を付けても効かない |
| テーブル所有者 | `FORCE ROW LEVEL SECURITY` が無ければバイパスする |
| `BYPASSRLS` 属性を持つロール | バイパスする |
| 非特権ロール | 正しく遮断される |

実測での確かめ方は、2 テナントぶんの行を入れて片方のセッション変数を立て、
もう片方が見えるかを見る。見えたら効いていない。

`current_setting('app.tenant_id', true)` は未設定なら空文字を返す。
これはどの行にも一致しないため、設定漏れは「全件見える」ではなく
「何も見えない」に倒れる。安全側なので、この挙動もテストで固定する。

## ファイル権限とコンテナ

| 条件 | 何が起きるか |
|---|---|
| root で実行 | ほとんどのファイル権限をバイパスする |
| コンテナの `--privileged` | ケーパビリティの制限が無効になる |
| bind mount | ホスト側の権限がそのまま効き、コンテナ内の設定を上書きする |

## API キーやシークレットのマスク

| 経路 | 何が起きるか |
|---|---|
| `fmt.Stringer` だけ実装 | 構造化ログ（`slog`）は `LogValuer` を見るため素通りする |
| `LogValuer` だけ実装 | `fmt.Printf("%+v")` で平文が出る |
| エラーの `%w` ラップ | 元の構造体が包まれて、上位で `%+v` されると漏れる |
| パニックのスタックトレース | 引数の値が出る処理系がある |

両方のインターフェースを実装し、両方の経路でテストする。

## キャッシュ

| 条件 | 何が起きるか |
|---|---|
| キーに可変オブジェクトを使う | ハッシュが毎回変わり、常にミスする（が結果は正しいので気づかない） |
| TTL が処理時間より短い | 実質毎回ミスする |
| プロセスごとのメモリキャッシュ | ワーカーが複数あればヒット率が 1/N に落ちる |

ヒット率を出さない限り、キャッシュを引いていないことに気づけない。
結果は常に正しいため、正しさのテストでは検出できない。

## レート制限とクォータ

| 条件 | 何が起きるか |
|---|---|
| 上限に達する前に測り終える | 制限が働かないまま「通った」と判定する |
| 別プロセス・別インスタンス | カウンタが共有されず、実効の上限が N 倍になる |
| リトライが内側にある | 1 回の呼び出しが複数回数えられ、想定より早く枯れる |

上限を意図的に超える入力を投げて、拒否されることを確かめる。

## ベクトル検索の索引

| 条件 | 何が起きるか |
|---|---|
| フィルタ条件を付けた検索 | プランナが索引を使わず逐次スキャンに落ちるか、横断してから絞って取りこぼす |
| データ投入前に索引を作る | IVFFlat は学習段階が必要で、再現率が落ちる |
| 索引を張り替え中 | DROP と CREATE の間は索引が存在しない |

再現率は「索引なしの結果」を正解として比較しないと測れない。
速度だけを見た比較は結論を誤らせる。

## エージェントのスキル・プラグイン

| 条件 | 何が起きるか |
|---|---|
| ディレクトリ階層が 1 段ずれる | 探索対象から外れ、警告もエラーも出ずに読み込まれない |
| 再起動していない | インストールは成功しているが一覧に出ない |
| 同名のスキルが別スコープにある | どちらが選ばれるかは配置による |

インストールの成功メッセージは「読み込まれたこと」を意味しない。
再起動後に一覧へ実際に名前が出るかを見る。

## 認可（誰が何をできるか）

| 条件 | 何が起きるか |
|---|---|
| チェックが入口だけ | 内部の別経路から到達できると素通りする |
| 拒否がデフォルトでない | 新しい経路を足したときに無防備になる |
| 管理者アカウントで検証 | すべて通るため、制限が効いているか分からない |

検証は必ず権限の低いアカウントで行う。
管理者で通ることは何も証明しない。
