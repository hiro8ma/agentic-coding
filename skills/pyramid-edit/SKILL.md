# ピラミッド原則で並べ替える

文書の中身は変えず、並びだけを「結論 → 根拠 → 詳細 → 次のアクション」に直す。

## 手順

1. 文書全体を読み、いちばん伝えたい結論を 1 文で書き出す
2. 結論を支える根拠を 2〜5 個に分け、それぞれにぶら下がる詳細を振り分ける。根拠は読み手の判断を左右する順に並べる
3. 結論、根拠、詳細の順に並べ替える。読み手や書き手が次にすることが文中に散らばっていれば、末尾に 1 か所へ集める。同じ階層の根拠は、同じ種類の分け方（時系列、重要度、構成要素など）にそろえる
4. 並べ替えた全文を見せ、確かめてもらってから上書きする

## 守ること

- 結論が文書の中に見つからないときは、結論を作らない。分かっていることと未確認のことに分けて並べ、結論が出ていないと利用者に伝える
- 元の文書が起きた順（経緯、詳細、問題、結論）に書かれていても、時系列の並びは残さない。経緯は詳細の階層へ移す
- 確認した事実、書き手の解釈、今後の対応が 1 つの段落に混ざっていれば、別の項目に分ける。文言は変えない
- 情報を落とさない。並べ替えるだけにし、削るのは明らかな重複だけにする
- 文字数が元の半分以下になったら、落とした情報がないかを点検する
- 上書きする前に、そのファイルが Git で追跡されていることを確かめる。追跡されていなければ、元の文書を残す
- 文の言い回しは直さない。直すなら `japanese-tech-writing` を使う
