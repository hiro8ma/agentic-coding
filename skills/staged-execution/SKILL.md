# 段階ごとの承認で書き込む

取り消しにくい操作を、読み取りと書き込みに分け、書き込みは 1 つずつ人の承認を取って進める。

## 手順

1. **読み取りで現状を確かめる**
   - SELECT、一覧の取得、設定の表示など、状態を変えない操作は確認なしで実行する
   - 依頼に書かれた「変更前」の値と、実際の値を比べる。違えば止めて、依頼した人に確かめる
   - 対象を探して 0 件や複数件が見つかったら、候補を示して選んでもらう
2. **プラン全体を見せる**
   - 実行するステップを、順番どおりにすべて並べる
   - 各ステップで何が変わるか（Before と After）を書く
3. **1 ステップずつ承認を取って実行する**
   - 実行の直前に、そのステップで実行するコマンドや SQL の全文を示す。要約ではなく全文にする
   - 承認を得てから実行する。1 回の承認で複数のステップをまとめて進めない
   - SQL は 1 回に 1 文にする
4. **実行した後に確かめる**
   - 読み取りで、意図した値になったかを確かめてから次のステップへ進む
   - 期待と違えば、次へ進まずに止めて報告する

## 本番に直接つながる場合

- 本番への書き込みは、人に実行してもらう
- 生成した SQL は `COMMIT` をコメントアウトして渡し、Before と After をコメントで書く
- 重複しそうな行や、停止済みの対象などに当たりそうなら、実行の前に警告する

## 組み合わせるスキル

- 実行した後の確認は `verify-mechanism` で、変更が本当に効いているかを対照で確かめる
