# 作業の進め方を週次で見直す

- 対象の問題と今回試した変更は〈変えた手順 / 適用したタスク〉
- 集計期間は〈開始日時 / 終了日時 / タイムゾーン〉、比較期間は〈同じ定義の期間〉
- データの参照先と取得時点は〈Issue / PR / レビュー / 再依頼の記録〉
- タスクとIssueとPRの対応は〈1作業 / 1Issue / 1PRの対応表〉

## 指標の定義

| 指標 | イベント基準 | 分母と集計対象 |
| --- | --- | --- |
| サイクルタイム | Issueの着手イベントから、対応するPRのマージまで | 期間内に完了し、両時刻を確認できたIssue数を添えて中央値を出す |
| 初回のレビュー待ち | PRの最初の明示的なレビュー依頼から、その後に人が最初のレビューを提出するまで | 期間内にこの区間が完了し、両時刻を確認できたPR数を添えて中央値を出す |
| マージ後の修正率 / revert率 | 元PRのマージから観測窓〈日数〉内にマージされ、元PRとの関連を確認できる修正 / revert | 期間内にマージした元PRのうち観測窓が満了したPRを分母とし、該当する元PR数を別々に数える |
| 同一タスクの再依頼数 | 初回依頼から観測窓〈日数〉内に、同じ成果を得るために再度作業を求めた明示依頼 | 期間内に初回依頼し、観測窓が満了したタスク数と、再依頼総数 / タスク数を併記する |

- Issueの着手イベントは〈状態遷移や着手記録の定義と取得元〉を先に決める
- PR作成からマージまでの時間を、Issue着手からマージまでの時間として扱わない
- レビュー待ちはbotの提出を除き、依頼なしのPRや未応答のPRを別に数える
- 計測のために新しいレビュー依頼を発行しない
- 再依頼と追加仕様は区別し、対応する記録がない再依頼を推測で数えない
- 欠測は件数と理由を併記し、0や別イベントへ置き換えない／分母0は算出不可とする
- 未完了のIssue / レビュー待ちと観測窓未満のPR / タスクは別件数にし、完了済みの分母へ混ぜない

## 結果と次の変更

- 結果は〈値 / 分母 / 欠測数 / 未完了数 / 比較期間との差〉
- 定義や対象が変わった箇所は〈比較できない理由〉として残す
- 数値の前後差だけからAIや手順の因果効果を断定せず、AIの確信度を合否に使わない
- 次に変える手順は〈観測した問題 / 変更案 / owner / 次回の確認方法〉
- 必須の定義やデータが未確認なら集計を未完了とし、確認事項と担当を残す
