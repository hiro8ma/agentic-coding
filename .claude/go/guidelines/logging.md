# ログ

構造化ログ（`log/slog` など）を前提にした規約。

## キーと値

- キーは snake_case にする（`user_id`、`request_id`）。ログの検索とダッシュボードで表記がそろう
- 値は `Any` ではなく、型の付いたフィールドで渡す

```go
// Bad
slog.Any("count", n)

// Good
slog.Int("count", n)
slog.String("user_id", id)
```

## ログレベル

誰が、いつ見るかでレベルを決める。

| レベル | 使いどころ |
|------|------|
| Error | 人が手で対応する必要があるもの。アラートの対象 |
| Warn / Info | 呼び出し元にエラーを返して処理が終わるもの。人の対応は要らない |
| Info / Debug | それ以外の、処理の経過 |

監視ツールが拾わない設定のレベルに、見逃したくないログを出さない。
どのレベルを監視ツールが拾うかを、先に確かめる。

## エラーとログ

- エラーを作るときにコード（種類）を持たせ、そのコードでログを出すかどうか、どのレベルで出すかを 1 か所で決める
- エラーを返す関数の中でもログを出し、呼び出し元でもログを出す、という二重の出力をしない
